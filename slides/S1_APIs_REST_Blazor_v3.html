Son proyectos separados corriendo al mismo tiempo
Tu app Blazor corre en el puerto 5001. La API corre en el puerto 7001. Ambos deben estar ejecutándose simultáneamente para que funcione — como dos programas abiertos al mismo tiempo en tu computadora.
JSON es el idioma en que las APIs responden. Es texto plano con una estructura de llave-valor. Fácil de leer para humanos y máquinas.
ejemplo.json JSON
{ "nombre": "Laptop Gaming", "precio": 15999.99, "disponible": true, "categoria": { "id": 3, "nombre": "Electrónica" } }
⚠️ Regla crítica
Los nombres de las propiedades en JSON deben coincidir exactamente con las propiedades de tu clase C#. Una letra diferente = dato vacío o error.
✅ Tipos de datos
String: entre comillas
Número: sin comillas
Boolean: true / false
Objeto: llaves { }
Arreglo: corchetes [ ]
Mira cómo el JSON de la API se convierte directamente en propiedades de tu clase C#.
JSON DE LA API
{ "temp": 28.5, "humidity": 72, "feels_like": 30.1 }
→
CLASE C# EQUIVALENTE
public class MainData { public double Temp { get; set; } public int Humidity { get; set; } public double Feels_Like { get; set; } }
🎯
¿Lo notaste?
feels_like en JSON → Feels_Like en C#. El deserializador de .NET es case-insensitive por defecto, pero si usas nombres muy diferentes necesitas [JsonPropertyName("feels_like")]. Esto explica por qué a varios compañeros les llegaban datos vacíos en la parcial pasada.

02
Registra HttpClient en Program.cs
▶
¿Por qué registrar HttpClient en Program.cs?
Blazor usa Inyección de Dependencias (DI). Es como un almacén central de servicios: primero registras lo que existe, y luego cualquier componente puede pedirlo. Si no registras HttpClient aquí, cuando tu componente lo pida con @inject, el sistema lanzará un error porque no sabe que existe.
¿Cómo funciona la Inyección de Dependencias?
Program.cs
builder.Services
.AddHttpClient();
① Registra el servicio
🏪 Contenedor DI
✅ HttpClient
+ otros servicios...
↓ entrega automática
Clima.razor
@inject HttpClient Http
② Lo pide y lo recibe
❌ Sin esta línea — el error que verías:
InvalidOperationException: No service for type 'HttpClient' has been registered.
Abre el archivo Program.cs
Agrega esta línea ANTES de builder.Build():
Program.csC#
// Registra HttpClient para que pueda inyectarse en cualquier componente builder.Services.AddHttpClient();

03
Crea las clases modelo en Models/WeatherData.cs
▶
¿Por qué necesito crear una clase C#?
La API responde con texto JSON. C# no puede usar texto directamente — necesita un molde que le diga cómo transformar ese texto en un objeto que puedas usar con punto: clima.Main.Temp. Esa clase es el molde. Sin ella, GetFromJsonAsync no sabe a qué tipo convertir la respuesta.
Cada campo del JSON necesita su propiedad en C# — haz clic para ver la conexión

"feels_like": 30.1
"humidity": 72
}
"description": "cielo claro"

}

Models/WeatherData.csC#
namespace ClimaApp.Models;   // Molde principal — mapea el JSON raíz de la API public class WeatherData { public MainData Main { get; set; } // ← "main": {...} public string Name { get; set; } // ← "name": "Colima" public List<WeatherDesc> Weather { get; set; } // ← "weather": [...] }   // Molde para el objeto anidado "main" public class MainData { public double Temp { get; set; } // ← "temp": 28.5 public double Feels_Like { get; set; } // ← "feels_like": 30.1 public int Humidity { get; set; } // ← "humidity": 72 }   // Molde para cada elemento del arreglo "weather" public class WeatherDesc { public string Description { get; set; } // ← "description": "cielo claro" }

04
Crea la página Clima.razor
▶
¿Qué hace cada parte de Clima.razor?
Un componente Blazor tiene 3 zonas: la directiva de ruta (qué URL lo activa), el HTML con Razor (lo que ve el usuario) y el bloque @code (la lógica C#). Aquí también usas @inject para recibir el HttpClient que registraste en el Paso 2.
Anatomía de Clima.razor — cada línea tiene un propósito
🗺️ Zona de directivas
@page "/clima" → Esta página responde a la URL /clima
@inject HttpClient Http → Pide el HttpClient al contenedor DI y lo llama "Http"
@using ClimaApp.Models → Importa las clases WeatherData, MainData, etc.
🖼️ Zona HTML + Razor
@if (clima == null) → Muestra "Cargando..." mientras espera la API
@clima.Main.Temp → Inserta el valor de la propiedad en el HTML
⚙️ Zona @code — Lógica C#
override async Task OnInitializedAsync() → Se ejecuta automáticamente al cargar la página
await Http.GetFromJsonAsync<T>(url) → Los 3 pasos: GET + recibe JSON + deserializa
¿Por qué async y await? — La diferencia visual
❌
Sin await
La página carga vacía. La petición se lanza pero no espera. clima sigue siendo null cuando el HTML se renderiza.
Datos vacíos en pantalla
✅
Con async/await
Blazor espera a que llegue la respuesta. Cuando clima tiene datos, el HTML se actualiza automáticamente con SignalR.
Datos reales en pantalla
Clic derecho en carpeta Pages → Agregar → Componente Razor
Nombre: Clima.razor
Reemplaza todo el contenido con este código:
Pages/Clima.razorC# / Blazor
@page "/clima" // ← Ruta de esta página @inject HttpClient Http // ← Recibe HttpClient del contenedor DI @using ClimaApp.Models // ← Importa WeatherData, MainData, etc.   <h3>🌤️ Clima en Colima</h3>   @if (clima == null) // ← Mientras espera la API { <p>Cargando datos del clima...</p> } else // ← Cuando ya llegaron los datos { <p>Ciudad: @clima.Name</p> <p>Temperatura: @clima.Main.Temp °C</p> <p>Sensación: @clima.Main.Feels_Like °C</p> <p>Humedad: @clima.Main.Humidity %</p> <p>Condición: @clima.Weather[0].Description</p> }   @code { private WeatherData? clima; // ← null al inicio, se llena después private string apiKey = "TU_API_KEY";   // Se ejecuta automáticamente al cargar la página protected override async Task OnInitializedAsync() { string url = $"https://api.openweathermap.org/data/2.5/weather?q=Colima&appid={apiKey}&units=metric&lang=es"; clima = await Http.GetFromJsonAsync<WeatherData>(url); // ← Los 3 pasos } }

¿Por qué necesito agregarlo al menú?
Tu página Clima.razor ya existe y responde a /clima, pero el usuario no tiene forma de llegar ahí si no hay un enlace visible. NavLink es un componente especial de Blazor que funciona como un <a> normal, pero además marca el enlace como "activo" automáticamente cuando estás en esa ruta.

¿Qué pasa exactamente cuando presionas F5?
Visual Studio compila tu código, lanza el servidor Blazor en un puerto local y abre el browser. Cuando navegas a /clima, Blazor ejecuta OnInitializedAsync, que hace la petición a OpenWeatherMap, recibe el JSON, lo convierte a WeatherData y actualiza la UI automáticamente.
Lo que ocurre en los primeros segundos al abrir /clima
1
Blazor carga el componente
clima es null → muestra "Cargando datos..."
2
Se ejecuta OnInitializedAsync
Envía HTTP GET a OpenWeatherMap con tu API key
3
Llega la respuesta JSON
GetFromJsonAsync lo convierte a WeatherData
4
Blazor re-renderiza la página
El @if detecta que clima ya no es null → muestra los datos ✅
